# 《西行拾卷》故事模式轻动作精修设计

- 状态：用户已批准设计方向
- 日期：2026-08-16
- 适用版本：当前 81 幕、17 个小游戏的无构建静态网页版本
- 核心选择：动作图集 + 共用轻动作引擎 + 每场首领专属机制

## 1. 目标

把当前可运行的小游戏原型精修成服务剧情的“故事模式轻动作”体验，同时解决舞台立绘尺寸跳变、发言者不够明亮、素材黑框、互动重复和结果反馈单薄的问题。

完成后应满足：

1. 战斗每场约 30 至 45 秒，剧情优先，失败成本低。
2. 悟空是唯一可控角色；八戒、悟净等只做协战演出，不切换操控。
3. 四场战斗拥有不同攻击规律，不再只是剧情立绘左右平移。
4. 蟠桃、盘丝和手势博弈均具有重玩变化、连击或读招空间。
5. 对话继续保持固定比例 Galgame 半身舞台，字幕框遮住立绘下部，点击字幕继续。
6. 所有新运行时人物素材具有真实 Alpha，不出现黑色或矩形底框。
7. 互动成绩进入旅痕与剧情回声，但绝不产生“悟空对悟空的好感”。
8. 现有 81 幕剧情、242 个选择、36 套声音签名和旧存档继续兼容。

## 2. 已有基线

当前版本已有 17 个互动：9 个剧情判断、2 个攻架变博弈、4 个横向战斗、2 个移动接物。运行时已经具备统一计时器、`requestAnimationFrame`、事件清理、失败重试、略过、键盘和触控入口。

本轮保留这些基础设施和 `story-branches.js` 中的场景配置，不重写剧情系统。精修重点是动作状态、敌人机制、结算指标、素材规范和舞台表现。

## 3. 产品不变量

### 3.1 原著与玩家身份

- 玩家始终扮演悟空；关系系统只记录其他角色对悟空的态度。
- 任何关系增减、因缘簿和后果弹签都过滤 `悟空` 与 `石猴` 自身键。
- 大圣时期、五行山获释时期和取经时期使用不同服装素材。
- 五行山获释前后不提前出现紧箍；观音安排花帽后才能切换取经期紧箍素材。
- 大闹天宫、二郎斗法、黑风山、红孩儿、火焰山的角色与事件顺序遵循现有原著主线。

### 3.2 Galgame 舞台

- 同一角色同一时期只有一个舞台视觉高度和脚底基线；换表情、动作时不得修改缩放比例。
- 字幕框固定在底部并遮住半身立绘下部；非选择台词点击整个字幕面继续，无独立“继续”按钮。
- 当前发言者必须明显提亮；旁观者保留可辨认轮廓，不得暗到看不清人物。
- 菩提祖师、悟净、黑熊精等深色素材使用角色级亮度补偿，不能只套统一滤镜。
- 进退场只允许纵向提签、轻微横移和透明度变化，不使用会造成忽大忽小的缩放动画。
- 演出描述统一为 `（……）`；不得出现“下一幕开始”“下一幕即将展开”等提示。
- 每幕结束都有幕布转场；普通换幕快速开合，章节换卷慢合、题签停顿后再开。

### 3.3 声音

- 沿用同源 `/api/tts`、`voice-cast.json` 和 36 套角色声音签名。
- 旁白继续使用雄厚、克制的成年男声；不同性别、年龄与身份使用各自配置。
- 演出描述不朗读；跳过、暂停、切换场景和进入小游戏时立即停止当前语音。
- 进入小游戏前停止当前对白；退出后由剧情流程决定是否继续下一句语音，战斗音效不得跨出小游戏生命周期。
- 现有静音开关同时控制语音和 WebAudio 音景，不额外增加第二套静音状态。

## 4. 技术架构

项目继续保持无打包、直接由浏览器加载的结构。

### 4.1 模块边界

- `story-branches.js`：只保存小游戏内容配置、奖励、剧情旗标和场景专属参数。
- `shadowplay-minigames.js`：新增共享运行时，负责输入、时钟、状态机、碰撞、敌人模式、成绩计算和清理。
- `shadowplay-runtime.js`：保留剧情流程、弹窗、存档、奖励结算与小游戏的打开/关闭，只通过公开接口挂载或销毁小游戏。
- `shadowplay-minigames.css`：新增战斗、接物、博弈、结算和响应式样式；舞台通用修复仍放在 `shadowplay.css`。
- `index.html`：在 `shadowplay-runtime.js` 前加载小游戏运行时和样式。

共享运行时暴露冻结的 `window.ShadowplayMinigames`，接口固定为：

- `mount({ game, root, sound, reducedMotion, onComplete })`，返回当前场次会话
- 会话方法 `destroy()`
- 会话方法 `restart()`

`destroy()` 必须取消全部 RAF、计时器、指针捕获和事件监听，并清空按键集合。剧情运行时仍是保存和奖励的唯一所有者。

### 4.2 配置模型

战斗配置在现有字段上增加：

- `playerVariant`：`great-sage` 或 `pilgrim-circlet`
- `encounter`：`heaven`、`black-wind`、`samadhi-fire` 或 `bull-demon`
- `timeLimit`：45 秒硬时限
- `parTime`：35 秒评级目标
- `patterns`：首领招式、预兆时长、伤害、冷却和阶段条件
- `assist`：只读协战演出配置
- `masteryReward`：甲级以上才触发的旗标或路线微量奖励

接物配置增加物件权重、连击窗口、完美接取范围和逐段加速；博弈配置增加候选读招池、种子和防重复规则。

配置读取失败时只降级当前互动：显示可继续的错误结算，不阻断剧情、不污染存档。

### 4.3 存档升级

`completedMiniGames` 单项从原有 `{ skipped, rewarded, score }` 扩展为：

```js
{
  version: 2,
  skipped: false,
  rewarded: true,
  score: 3,
  grade: "A",
  metrics: {
    elapsedMs: 34620,
    remainingHealth: 68,
    maxCombo: 7,
    preciseCounters: 3,
    hitsTaken: 2
  }
}
```

读取旧存档时缺失字段使用默认值，不重新发放旧奖励。分数回算仍以场景索引为界，防止读档后重复叠加路线和关系值。

## 5. 战斗系统

### 5.1 共用操作

- 移动：`A/D` 或方向键；触控使用左右按钮，鼠标可按住同一按钮。
- 轻击：`J` 或短按攻击键。
- 蓄力：按住攻击键 420 毫秒后释放；威力更高但露出破绽。
- 闪避：`K` 或 `Shift`；具有短暂无敌时间和明确冷却。
- 精准反击：在敌人命中前 180 毫秒内用轻击截断，可造成额外硬直。

人物状态机固定为 `idle`、`move`、`attack`、`charge`、`dodge`、`hit`、`victory`、`defeated`。同一状态未结束前不被低优先级状态覆盖，避免连续输入造成闪图。

移动和碰撞仍采用一维舞台，保持故事模式易读性；投射物和地面危险是独立实体。所有数值使用基于时间的更新，刷新率变化不能改变移动速度或伤害频率。

### 5.2 难度与失败

- 每战目标 30 至 45 秒，普通玩家两次尝试内能够完成。
- 悟空生命归零或超时后进入未竟结算，可重试或保留结果继续。
- 重试重新初始化随机种子、生命和指标，不重复发奖。
- 略过不给小游戏奖励，但继续进入本幕选择，不改变主要剧情旗标。
- 减少动态效果时保留完整判定窗口，只移除镜头震动、拖影和大幅位移。

### 5.3 四场专属机制

#### 大闹天宫 `1:5`

- 第一阶段为李靖前锋阵：天兵从两侧压近，长枪出现直线朱砂预兆。
- 第二阶段是哪吒：火尖枪近战与回旋火轮交替；火轮去程和回程均可闪避。
- 群猴只在满足连续反击条件时触发一次清场演出，不可操控。
- 核心考验是移动、连续轻击和识别投射物回程。

#### 黑风洞 `3:6`

- 黑风周期性压暗远处轮廓，但兵器闪光和攻击预兆始终保持高对比度。
- 黑熊精有真蓄力和假蓄力；假动作提前收枪，贸然闪避会失去反击窗口。
- 观音仅在战斗结束后的剧情中出现，不在玩家战斗中直接代打。
- 核心考验是观察闪光、延迟闪避和精准反击。

#### 火云洞 `5:5`

- 三昧火先标出左、中、右火路，再依次喷发；安全路线每轮变化。
- 红孩儿连续喷火后必须换气，形成稳定的蓄力攻击窗口。
- 火焰命中会短时增加热势，但不永久遮住玩家或按钮。
- 核心考验是路线判断、闪避和抓住换气破绽。

#### 翠云山 `7:2`

- 第一阶段使用混铁棍横扫和震地，震地必须闪避而不能轻击截断。
- 第二阶段现出牛魔本相，先显示冲撞方向，再高速穿场；撞墙后进入硬直。
- 八戒在玩家完成两次精准反击后触发封路演出，只延长硬直，不造成决定性伤害。
- 借扇选择旗标改变场景台词与火势强弱，但不无条件改变胜负。
- 核心考验是招式分类、诱导冲撞和协战时机。

## 6. 非战斗互动

### 6.1 蟠桃园接桃 `1:2`

- 熟桃连续接取形成连击；两秒内没有接到目标则连击归零。
- 接取中心与悟空手部中心误差不超过容器宽度的四分之一时记为完美接取。
- 青桃扣一分但不打断操控；巡园天册扣一次护身并清空连击。
- 连击提高落物速度但不改变碰撞尺寸；最高速度受手机屏幕刷新率保护。
- 结算记录熟桃、完美接取、最大连击、误接青桃和碰到天册次数。

### 6.2 盘丝洞寻隙 `7:8`

- 金色破绽按左右受力顺序出现，连续接取会展开一条可见的断网路径。
- 普通蛛网使护身减一；收紧蛛网会短暂限制移动，但不让玩家失去全部控制。
- 连续三次抓住破绽触发一次金箍棒断网演出，并延缓下一批蛛网。
- 结算记录破绽、最大连续数、碰网次数和剩余时间。

### 6.3 攻架变博弈 `1:6`、`6:7`

- 每局从场景专属读招池中抽取五手，不能再按固定顺序背答案。
- 同一对手不得连续三手使用相同招式；五手中三种招式至少各出现一次。
- 提示文字与手势动作共同提供线索，线索必须能可靠推导，而不是纯随机猜拳。
- 使用保存中的场景键与尝试次数构造种子；单次重试会换序，复盘同一已完成结果不会变更。
- 二郎的提示偏兵器、肩线和天眼；六耳的提示偏模仿延迟、听觉和旧经历。

## 7. 美术资产

### 7.1 目录

运行时动作素材按角色和时期保存：

```text
assets/minigames/fighters/
  wukong/great-sage/
  wukong/pilgrim-circlet/
  heaven-soldier/
  nezha/
  black-bear/
  red-boy/
  bull-demon/
assets/minigames/effects/
assets/minigames/source-sheets/
```

每个运行角色至少有待机、移动、攻击、蓄力、闪避或回避、受击、胜利或败退状态。悟空两种时期分别制作，禁止以改色代替服装差异。

源动作图集保存在 `source-sheets`，运行时导出为独立透明 PNG，便于逐状态校正锚点。新增素材写入 `ASSET_MANIFEST.md` 并记录用途、尺寸、Alpha 检查和引用场景。

### 7.2 规格

- 单帧统一透明画布，站立动作的脚底锚点为画布宽度 50%、高度 94%；腾跃和闪避状态使用显式锚点元数据。
- 同一角色同一时期以头部和躯干参考线校准解剖比例，参考尺度差不得超过 3%；蹲身、腾跃等动作允许轮廓高度自然变化。
- 所有四角 Alpha 必须为 0；可见矩形底、黑边和导出底色均视为失败。
- 武器和飘带允许越过主体安全框，但不能被运行时容器裁断。
- 移动依靠舞台位置变化，CSS 不通过改变图片宽高制造动作。
- 战斗特效独立于人物图：棒风、命中火花、三昧火、黑风、火轮、冲撞尘浪和蛛网断裂。

### 7.3 对话立绘同步修复

- 以“角色 + 时期”为单位审计所有表情图，统一内容包围盒和舞台基线。
- `actorFraming` 不再按每句表情改变缩放，仅允许同一时期共享缩放和小范围位移。
- 新增角色级 `focusBoost`，为菩提、悟净等深色角色补偿亮度与对比度。
- 发言者状态切换只替换图片和表情数据，不触发重新入场或缩放动画。
- 现有 109 个图片资产全部执行尺寸和引用检查；其中角色、特效和小游戏前景素材额外执行透明角与边界框检查，运行时可见的矩形底必须清零。

### 7.4 战斗场景状态

- 花果山增加天兵压阵与火轮掠场两种光影状态。
- 黑风洞增加洞口可见、黑风遮场和兵器闪光三层，不用纯黑遮罩隐藏玩法信息。
- 火云洞增加三条可读火路和换气熄火状态。
- 翠云山增加混铁棍阶段、本相冲撞阶段和芭蕉火势差异。
- 蟠桃园与盘丝洞分别增加连击风动和断网路径前景；这些前景与背景分层，不能把交互提示烘焙进静态图。

## 8. HUD、反馈与剧情回声

### 8.1 HUD

- 战斗顶部只显示悟空生命、首领生命、阶段名和剩余时间。
- 蓄力和闪避冷却直接显示在对应操作键上，不额外堆叠说明卡片。
- 手机控制区高度固定，动态文字不能挤压战斗场地。
- 危险预兆同时使用形状、动画和声音，不只依靠红色。

### 8.2 结算

所有动作小游戏计算 0 至 100 的表现分，再映射：`S >= 90`、`A >= 75`、`B >= 60`、`C >= 40`、`D < 40`。所有分项先钳制到 0 至 1，再按权重相加并四舍五入：

- 战斗：敌人累计生命削减比例 50%，剩余生命比例 20%，`min(精准反击数 / 3, 1)` 占 15%，`max(1 - 受击数 / 5, 0)` 占 10%，完成后从 `parTime` 到 `timeLimit` 线性衰减的时间比例占 5%。
- 接物：目标完成比例 50%，剩余护身比例 15%，`min(最大连击 / 5, 1)` 占 15%，完美接取数除以有效目标接取数占 10%，完成后从 `parTime` 到 `timeLimit` 线性衰减的时间比例占 10%。
- 博弈：胜手比例 70%，`min(最大连胜 / 3, 1)` 占 20%，平手比例占 10%。

结算展示用时、生命或护身、最大连击、精准反击等实际指标。达到原有通过线即可领取基础奖励；`S/A` 可写入一个场景专属精通旗标并领取配置中的微量路线奖励。关系值只在剧情上合理时变化，且每场最多涉及两个非玩家角色。

### 8.3 回声

- `1:5` 的守山评价影响 `1:6` 二郎对悟空战法的评价。
- `3:6` 的读招评价影响观音收黑熊后的台词。
- `5:5` 的火路评价影响 `5:6` 观音收伏红孩儿时的反馈。
- `7:2` 的协战评价与借扇旗标共同影响 `7:3` 熄火台词。
- `7:8` 的断网评价影响师徒脱困后的短回声。
- 回声只增加台词和后果反馈，不跳过原著必经事件。

右上角反馈仍使用后果章记：只在明显结果发生时出现，并显示具体旗标含义或角色关系变化，不为每次普通操作弹窗。

## 9. 输入、无障碍与生命周期

- 键盘、鼠标、触控执行同一动作函数，不维护三套规则。
- 页面失焦、`visibilitychange`、打开暂停菜单和关闭小游戏时清空按键并暂停时钟。
- 焦点进入小游戏后限制在弹层内；结束后返回原字幕或选择按钮。
- 触控按钮最小点击区为 44×44 CSS 像素，支持多指同时移动和攻击。
- `prefers-reduced-motion` 下关闭震屏、拖影、快速闪白和大幅提签，保留攻击预兆时长与状态反馈。
- 音效提示都有同步的视觉形状；颜色变化都有文字或图形状态。
- 画布逻辑区固定宽高比，窄屏使用等比缩放和安全边距，不因 HUD 文本改变尺寸。

## 10. 错误处理

- 图片加载失败时显示该角色的既有安全立绘，并记录一次控制台警告；不显示破图图标。
- 单个招式配置非法时跳过该招式；整场没有合法招式时进入可继续的未竟结算。
- 音效或语音失败不影响输入和动画。
- 存档指标非法时钳制到合法范围；无法识别的 `version` 只读取旧有 `score/skipped/rewarded`。
- 所有退出路径共用 `destroy()`，包括完成、失败、略过、重试、暂停跳转和页面离开。

## 11. 测试与验收

### 11.1 自动测试

扩展 `tests/runtime-regression.cjs` 并新增小游戏引擎测试，断言：

1. 81/81 幕定制选项、242 个选项和现有回声继续通过。
2. 17 个小游戏仍完整存在，类型分布保持 9/2/4/2。
3. 每个战斗配置具有合法角色时期、专属机制、动作素材和 30 至 45 秒目标时长。
4. 博弈种子可复现、顺序可变化、不会连续三手相同且三种招式均出现。
5. 成绩阈值、基础奖励、精通奖励和旧存档迁移不会重复计分。
6. 所有关系奖励角色存在于 `characterInfo`，并且不包含悟空或石猴。
7. RAF、计时器、监听器和按键在全部退出路径后归零。
8. 所有运行时 PNG 有 Alpha，四角透明，角色包围盒符合统一比例。
9. 运行时与语音测试继续禁止“下一幕开始”文本，演出描述不进入 TTS。

`tests/voice-regression.cjs` 必须继续验证 36 套声音签名、旁白男声、角色性别和神经语音预取缓存。

### 11.2 浏览器验收

使用桌面 `1440×900`、窄屏 `390×844` 和横屏手机 `844×390` 检查：

- 四场战斗可完成、失败、重试和略过。
- 键盘、鼠标、单指和多指输入均无粘键。
- 悟空与敌人动作切换不跳尺寸、不裁武器、不残留黑框。
- 字幕框稳定遮住半身下部，换表情时人物视觉高度不变。
- 菩提祖师、悟净和其他深色人物在发言时明显亮于旁观状态。
- 暂停、继续、切幕和读档不会残留音效、语音或战斗循环。
- 减少动态效果模式可完整游玩。

截图验收必须实际由浏览器完成；浏览器不可用时明确记录为未验证，不能以静态检查冒充截图验证。

### 11.3 性能预算

- 单场战斗新增运行时图片总量控制在 28 MiB 内。
- 首次进入战斗前只预载当前悟空时期、当前敌人和通用特效。
- 同时活动的投射物与落物数量设硬上限，离场实体立即移除。
- 桌面目标 60 FPS，移动端最低可接受 30 FPS；低帧率不改变计时和碰撞结果。

## 12. 实施顺序

1. 建立共享小游戏运行时与兼容适配，保持当前画面和结果不变。

## 13. 非目标

- 不制作高难度连招、装备成长、角色切换、联网排行或自由地图。

- 不在本轮重新录制真人配音；现有专业神经语音接口、角色声线配置和替换接口保持可用。
- 不进行与舞台、小游戏、结果回声和相关素材无关的页面重构。
